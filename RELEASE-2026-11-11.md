## Headline: per-agent budgets

`policy.agents` gives each agent its own ceiling, payee list and network list, as a
**narrowing overlay** on the global policy. Two properties make it safe:

- overrides may only narrow — raising a ceiling, adding a payee, or loosening `deny` to
  `review` is rejected before it applies
- identity fails closed — once agents are declared, a missing or unknown `agent_id` is a
  denial, never a fallback to the loosest rules in the file

The test that matters: a 0.20 USDC payment is `pay` under the global 1.00 ceiling and
`do_not_pay` for the agent whose ceiling is 0.05.

## Second: receipts became checkable

`paystage-verify` fetches the published key and verifies ECDSA-P256 over the canonical
payload. Exit codes separate **invalid** (1), **unsigned** (2) and **unverifiable** (3).
Two details decide whether it works at all — byte-identical canonicalisation, and
`dsaEncoding: ieee-p1363` (WebCrypto emits raw `r||s`, Node defaults to DER).

## Release procedure

```sh
git checkout main && git pull
npm run build && npm run typecheck && npm test   # all green as of writing
git tag v2026.11.11
git push origin v2026.11.11                      # Dave only
```

`release.yml` publishes every package whose version is not already on npm, in dependency
order, with provenance via OIDC, then (once the patch is applied) pushes each
`server.json` to the MCP registry.
